# P5: family error causes through the three layers

## Built
`src/p5_error_causes.rs`: `find_cause::<E>(&dyn Error) -> Option<&E>` (walks `source()`, starting at the
error itself) and `chain_type_names` (diagnostic). `tests/p5_error_causes.rs` drives real failures through
concrete (`CpuEngine` + `TensorLinalgExt` / `[&a,&b].einsum`), traced (`TraceContext` -> `GraphCompiler::compile`
-> `Runtime::prepare/run`, same harness as tenferro-linalg's `tests/integration/support.rs`), and eager
(`EagerRuntime::with_eager_session` + `EagerSessionLinalgExt` / `EagerSessionEinsumExt`).

## Tests
`RUSTFLAGS="-Zcrate-attr=feature(atomic_try_update)" cargo +nightly test --ignore-rust-version -p tenferro-api-grammar-proof --test p5_error_causes`
-> **9 passed, 0 failed, 0 ignored.**

## Results (what the code does today)
| failure | layer | outer type | kind() | `find_cause::<tenferro_linalg::Error>` |
|---|---|---|---|---|
| cholesky, indefinite | concrete | `tensor::Error::Extension` | NumericalFailure | yes: `NonConvergence{cholesky}` |
| cholesky, indefinite | traced (fails at **run**, compile ok) | `runtime::Error::TensorRuntime(tensor::Error::Extension)` | NumericalFailure | yes, same |
| cholesky, indefinite | eager (fails at call) | `tenferro_ad::Error` (= `runtime::Error`) `TensorRuntime(..)` | NumericalFailure | yes, same |
| solve, singular | concrete | `tensor::Error::Extension` | NumericalFailure | yes: `Singular{solve}` |
| solve, singular | traced | `runtime::Error::TensorRuntime(..)` | NumericalFailure | yes: `Singular{lu_factor_solve}` |

Linalg causes are **not** stringified in any layer; `kind()` equals `cause.kind()` and the cause message is
contained in the outer `Display`.

| einsum failure | concrete | traced | eager |
|---|---|---|---|
| `"ab,bc->ac->x"` (parse) | `einsum::Error::InvalidSubscripts` | same | same |
| `"ab,bc->zz"` (missing label) | `InvalidSubscripts` | `einsum::Error::Runtime(runtime::Error::Extension{..})` -> `Metadata` -> `ValidationError::InvalidArgument` | `InvalidSubscripts` |
| `"ab,bcd->ac"` (rank) | `Validation(RankMismatch)` | `Runtime(Extension)`, kind **InvalidArgument**, cause `RankMismatch` | `Validation(RankMismatch)` |

## Findings (grammar vs code)
1. **`tenferro_ad::Error` is `tenferro_runtime::Error`** (ad lib.rs:103 re-export), so "one outer type per
   layer: tensor / runtime / ad" is really two types. Eager and traced share one.
2. **einsum breaks the three-outer-types rule outright.** Concrete, traced and eager einsum all return
   `tenferro_einsum::Error` (its own enum wrapping `tensor::Error` and `runtime::Error` via `#[error(transparent)]`),
   not `tensor::Error`/`runtime::Error`/`ad::Error`. For einsum the "family error" is the outer error, and
   `find_cause::<tenferro_einsum::Error>` succeeds only because it IS the top of the chain (chain length 1).
   Eager `with_eager_session` is generic over the callback's error type (`E: From<Error>`, eager.rs:3143), which is
   what lets einsum choose its own.
3. **Transparent wrappers hide a layer.** `runtime::Error::TensorRuntime` (error.rs:215) and `einsum::Error::{Tensor,Runtime}`
   are `#[error(transparent)]`, whose `source()` forwards to the inner error's source. So
   `find_cause::<tenferro_tensor::Error>` is **None** on traced/eager errors even though a `tensor::Error` is wrapped;
   only a `match` on the variant reaches it. The grammar says causes must be reachable by `source()/downcast_ref`; family
   causes are (linalg), but the intermediate layer error is not. Same for the traced einsum chain.
4. **kind and cause can diverge.** Traced `"ab,bcd->ac"`: outer `kind()` = `Validation(InvalidArgument)` while the reachable
   cause is `ValidationError::RankMismatch` (kind RankMismatch); concrete and eager report RankMismatch. The extension
   boundary re-kinds on the way up. Pinned by `einsum_rank_mismatch_kind_and_cause_disagree_in_traced_layer`. This
   confirms the proposal's warning that a kind/cause mismatch must be caught by tests; it exists today.
5. **The same bad spec yields different causes per layer** (`"ab,bc->zz"`: parser error in concrete/eager, graph-build
   validation error in traced), so a caller cannot match one cause type across layers.
6. **Linalg op names differ across layers**: concrete `Singular{op:"solve"}`, traced `Singular{op:"lu_factor_solve"}`
   (the lowered kernel). Cholesky of a non-PD matrix is classified `NonConvergence` (no positive-definiteness variant);
   `Singular` and `NonConvergence` are the only numerical linalg variants a user can hit here.
7. Traced numerical failures are **deferred**: build and `compile` succeed, `prepare`/`run` fail.
8. Traced `TraceContextEinsumExt::einsum` takes `&mut self` (traced.rs:59), unlike the proposal's `trace.einsum(&[a,b], spec)`
   on a shared receiver (relevant to P6).

## Not verified
Non-CPU engines; stringification inside paths I did not run (autodiff/backward, `Error::BackendSource`, extension
errors from `fft`); `Display` formatting stability; eager `solve`; `ExtensionModule` third-party families;
whether any `From<..>` conversion elsewhere (e.g. `map_error`, `Error::into_tensor_error`) formats a typed cause
(I only checked `source()` reachability on the five failures above).
