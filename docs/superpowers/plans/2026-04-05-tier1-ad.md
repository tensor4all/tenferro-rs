# Tier-1 AD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement forward-mode (JVP) and reverse-mode (VJP) automatic differentiation for the 11 Tier-1 tensor ops via method-based `TracedTensor::jvp(&x, &tangent)`, `TracedTensor::vjp(&x, &cotangent)`, and `TracedTensor::grad(&x)` (scalar output convenience), connecting tenferro-ops to tidu-rs.

**Architecture:** AD is a lazy graph transform. `y.grad(&x)` calls `tidu::differentiate` + `tidu::transpose` and returns a new `TracedTensor` (no eval yet). `engine.eval_all(&mut [&mut y, &mut grad_x])` resolves all fragments together, deduplicating shared primal nodes. Each Tier-1 op gets `linearize` + `transpose_rule` in `tenferro-ops/src/ad/`. Ops that need original input shape in their transpose rule store it in the op variant (`Reshape { from_shape, to_shape }`, `ReduceSum { axes, input_shape }`).

**Tech Stack:** chainrules-rs (`PrimitiveOp`, `ADKey`), tidu-rs (`differentiate`, `transpose`), computegraph-rs (`FragmentBuilder`, `OpMode`)

**Reference (within this repo):**
- Execution layer spec: `docs/superpowers/specs/2026-04-05-execution-layer-separation-design.md`
- AD seed semantics: `docs/design/autodiff.md:145`
- Repository rules: `REPOSITORY_RULES.md`

**External reference (separate repos, not required for plan execution):**
- tidu-rs scalar AD pattern: `../tidu-rs/tests/common/mod.rs` (template for linearize/transpose_rule)
- v2 pseudocode: `../tensor4all-meta/docs/design-v2/examples/tensor-api-pseudocode.md`

**AD-closed Tier-1 set:** Add, Mul, Neg, Conj, DotGeneral, Transpose, Reshape, BroadcastInDim, ReduceSum, ExtractDiag, EmbedDiag

## Phase 3: TracedTensor Integration

### Task 8: Implement TracedTensor::jvp, vjp, and grad

**Files:**
- Modify: `tenferro/src/traced.rs`

Following v2 pseudocode: `y.jvp(&x, &tangent)`, `y.vjp(&x, &cotangent)`, and `y.grad(&x)` are lazy — they return `TracedTensor` with `data = None`. Actual evaluation happens via `eval` / `eval_all`.

**Seed semantics:** `grad` is only valid for scalar outputs (`num_elements == 1`). For non-scalar outputs, use `vjp` with explicit cotangent. See `docs/design/autodiff.md:145`.

- [ ] **Implement `jvp(&self, wrt: &TracedTensor, tangent: &TracedTensor) -> TracedTensor`**:
  1. Extract `wrt` input key from fragment
  2. `resolve(vec![self.fragment])` → `ResolvedView`
  3. `tidu::differentiate(&view, &[output_key], &[wrt_key], pass_id)` → `LinearFragment`
  4. Build new `TracedTensor` with:
     - `fragment = linear.fragment`
     - `val = tangent_output local id`
     - `data = None`
     - `inputs_map` merges primal inputs + tangent input (mapped to `tangent.data`)
  5. Increment global DiffPassId counter

- [ ] **Implement `vjp(&self, wrt: &TracedTensor, cotangent: &TracedTensor) -> TracedTensor`**:
  1. Same as jvp steps 1-3
  2. `tidu::transpose(&linear)` → `LinearFragment` (transposed)
  3. Build `TracedTensor` with transposed fragment
  4. `inputs_map` maps cotangent seed input to `cotangent.data`

- [ ] **Implement `grad(&self, wrt: &TracedTensor) -> TracedTensor`**:
  Convenience wrapper for scalar outputs. Asserts `self.shape.iter().product::<usize>() == 1`,
  then calls `self.vjp(wrt, &ones_seed)` where `ones_seed` is a `TracedTensor::from(Tensor::ones([1]))`.
  Non-scalar output → return `Err(Error::NonScalarGrad)`.

- [ ] **Verify `eval` and `eval_all` work with AD fragments**:
  The existing `eval` / `eval_all` in `traced.rs` already handle multi-fragment resolution. AD fragments reference primal values via `External(GlobalValKey)`, which `materialize_merge` resolves.

- [ ] `cargo check -p tenferro`
- [ ] Commit: `feat: implement TracedTensor::grad and jvp via tidu`
