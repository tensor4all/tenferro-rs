# Ubuntu 24.04 CI baseline

## Decisions

The maintainer requested one Ubuntu 24.04 baseline. The official RunPod runner
image and hosted runtime preparation already use it; archive builds, cache
publication and several CPU jobs still used 22.04. All repository-owned Linux
jobs now explicitly select 24.04, including jobs that previously used the moving
`ubuntu-latest` alias. macOS remains on its existing platform.

NVIDIA supports 24.04 in both [CUDA 12.6](https://docs.nvidia.com/cuda/archive/12.6.3/cuda-installation-guide-linux/index.html)
and [CUDA 12.8](https://docs.nvidia.com/cuda/archive/12.8.0/cuda-installation-guide-linux/).
Installers use the matching `ubuntu2404` repository. CUDA archive, toolkit,
runtime and Linux Rust caches get distinct namespaces so old OS artifacts
cannot masquerade as the new baseline. The distribution-independent cuTENSOR
runtime cache and the public Actions runner image digest stay unchanged.
No Rust API, numerical operation, CUDA version or test selection changes.

The organization-managed `ubuntu-gpu` fallback is an external configuration.
Its image metadata API returned HTTP 403 because runner-administration
permission is unavailable. The repository can enforce the 24.04 prerequisite
before consuming its new archives, but cannot change that image itself. This
does not affect normal RunPod validation. The durable platform contract is in
[change-aware CI](../design/change-aware-ci.md#ubuntu-ci-baseline).

## Verification conclusions and constraints

Local CI helper tests, actionlint and the fast gate pass, including a real
shell check accepting Ubuntu 24.04 and rejecting 22.04 before legacy GPU
archive execution. The unchanged official Actions runner image identifies as
Ubuntu 24.04, and apt simulation resolves the complete runtime/toolkit package
sets for both CUDA tiers using NVIDIA's 24.04 repository. Both pinned NVRTC
package hashes match the new repository's published package index exactly;
the versions and bytes are unchanged.

Hosted CPU checks and the complete GPU workload must validate the changed
platform. The trusted RunPod controller uses main's workflow definition during
PR checks, so a post-merge run is required to establish that both compilation
and execution use 24.04. Cold caches are expected after namespace rotation;
this migration carries no timing or cost-improvement claim.
