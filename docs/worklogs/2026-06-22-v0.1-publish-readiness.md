# v0.1 Publish Readiness

## Scope

This is the pre-publish checklist for the tenferro-rs v0.1 crate set. It keeps
the repository ready for `cargo publish` without publishing anything from this
branch.

## Dependency Prerequisites

Publish or confirm these crates before publishing tenferro crates:

- `t4a-cubecl*` version `0.10.0` from the tensor4all CubeCL fork.
- `t4a-cubek*` version `0.2.0` from the tensor4all CubeK fork.
- `computegraph`, `tidu`, and `strided-*` crates at the versions declared in
  the tenferro workspace manifest.

Before the fork crates are on crates.io, the workspace may use Cargo's
`git`+`version` dependency form so local checks use the fork commit while the
packaged manifest has registry version requirements.

## Tenferro Publish Order

Publish low-level implementation crates first, then backend/runtime crates, then
operation-family crates:

1. `tenferro-tensor-core`
2. `tenferro-core-ops`
3. `tenferro-internal-extension-macros`
4. `tenferro-tensor`
5. `tenferro-internal-ops`
6. `tenferro-cpu`
7. `tenferro-gpu`
8. `tenferro-runtime`
9. `tenferro-xla`
10. `tenferro-ad`
11. `tenferro-einsum`
12. `tenferro-linalg`
13. `tenferro-fft`

`tenferro-internal-ops` is publishable even though it is not user-facing API:
published tenferro crates depend on it, so it must exist in the registry.

## Final Morning Checks

Run these after dependency crates are published and before the real publish:

```bash
cargo fmt --all --check
python3 scripts/check-publish-layout.py
cargo package -p tenferro-tensor-core --allow-dirty
cargo package -p tenferro-core-ops --allow-dirty
cargo package -p tenferro-internal-extension-macros --allow-dirty
cargo package -p tenferro-tensor --allow-dirty
cargo package -p tenferro-internal-ops --allow-dirty
cargo package -p tenferro-cpu --allow-dirty
cargo package -p tenferro-gpu --no-default-features --features webgpu --allow-dirty
cargo package -p tenferro-runtime --allow-dirty
cargo package -p tenferro-xla --allow-dirty
cargo package -p tenferro-ad --allow-dirty
cargo package -p tenferro-einsum --allow-dirty
cargo package -p tenferro-linalg --allow-dirty
cargo package -p tenferro-fft --allow-dirty
```

After `t4a-*` packages are available from crates.io, remove the temporary
`git`/`rev` keys from their dependency declarations and keep the exact version
requirements.
