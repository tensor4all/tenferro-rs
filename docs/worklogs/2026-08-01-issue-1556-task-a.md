## Classification and contract tests

- Auto Fix: the two independent review findings are existing atomic
  reconfiguration contracts and an internal immutable-map/performance
  boundary, all covered by current Task A behavior.
- Added
  `reconfiguration_remove_engine_rejects_dangling_route_atomically_and_keeps_same_route_executable`.
  Its only published route names the engine being removed. The test checks the
  exact `UnknownTransferEndpointEngine` endpoint, unchanged epoch/engine and
  route counts, no snapshot publication, old-snapshot readability, and
  post-failure execution of that same route through the old provider.
- Added
  `reconfiguration_replace_engine_rejects_dropped_route_storage_atomically_and_keeps_same_route_executable`.
  Its only published route names the storage class removed by the replacement.
  It checks the corresponding exact `UnsupportedTransferEndpointStorage`
  endpoint and the same atomicity, snapshot, route, and execution contracts.
- The first focused run exposed only an overly permissive test fixture: a host
  input was accepted directly by the destination engine and bypassed the
  intended route. The reusable published-route fixture now uses distinct
  source and destination allocation domains and records the exact endpoint
  pair received by the affected provider; both failure tests execute that
  same route after rejection. No remove/replace-specific production logic was
  added.

## Decisions

- Added one crate-private `TransferRoute` key with private source and
  destination `TransferEndpoint` fields and accessors. Candidate maps,
  frozen snapshots, preparation reachability, scheduling, and execution all
  use it instead of endpoint tuples.
- Candidate reconfiguration keeps a mutable owned `BTreeMap<TransferRoute,
  Arc<dyn TransferProvider>>`. A frozen `RuntimeConfigSnapshot` owns an
  `Arc<BTreeMap<TransferRoute, Arc<dyn TransferProvider>>>`; prepared
  execution Arc-clones that map, so each run does not clone the full provider
  map while old snapshots retain their own immutable route state.
- Candidate validation remains the shared complete-candidate/freeze boundary;
  failed engine removal or replacement therefore cannot publish dangling or
  unsupported routes.
- Updated the architecture design's stale storage-class-pair routing wording
  to endpoint-pair routing.
- Added runnable rustdoc examples for both public transfer-registration
  methods. They use real endpoint-pair registration and contain no
  `ignore`/`no_run` escape hatch.
