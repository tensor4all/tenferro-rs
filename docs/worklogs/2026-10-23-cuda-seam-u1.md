## What landed

The new backend path lives behind the `cuda-next` feature and is private: the public
`cuda::` names keep the CubeCL implementation until the operation surface moves over
(U2-U6), as the parent design requires ("no dual-storage switch").

- `src/gpu/` — the backend-neutral seam: `GpuError`/`SeamError`, `StorageIdentity` +
  `Buffer`, the opaque `Program`/`OpDescriptor`, the two provider traits
  `KernelSource`/`VendorOps` with their call descriptors, and a shared counter
  snapshot. No CUDA type appears there.
- `src/cuda_next/` — the CUDA adapter over `t4a-cuda-runtime` (git revision
  `0a101bf`, which pins cudarc 0.19.10, the version this workspace's lock selects):
  - `CudaRuntime`: a cloneable handle owning one `Mutex<t4a_cuda_runtime::Runtime>`,
    the device metadata, the allocation-domain identity, the runtime's counters and
    the compatibility package's detached-handle queue. Explicit host transfers take
    the runtime's submission lock for one admission; numerical submission stays with
    the engine.
  - `CudaEngine`: `Send`, `!Sync`, one runtime; `publish` records one checkpoint as a
    value's frontier, `copy_to` moves a value to another engine, and `Drop`
    synchronises best-effort so a publication frontier is complete when the engine
    goes away.
  - `CudaStorage`: a `t4a-cuda-runtime` allocation behind `BackendStorage<T>` with a
    stable allocation id; `PinnedHostBuffer`; `upload_tensor`/`download_tensor`;
    `upload_pending`/`download_pending` with `is_ready`/`wait`, drop-detach,
    forget-leak and package-returning rejections; `SourcePublication` with
    `frontier_ready`/`await_frontier`/`download_into`.

this slice.

## Deviations and observations (recorded, not hidden)

- **Device discovery is still the existing metadata probe.** The runtime exposes the
  device count, name and kernel-parameter limit, but not the UUID, compute capability
  and total memory `CudaDeviceInfo` carries; U1 therefore reuses the existing probe
  (a cudarc call, not a CubeCL one) and leaves a runtime-backed probe to U6.
- **`Completion::poll` also reclaims completed work.** Polling a checkpoint first runs
  the runtime's observation, which settles completed staging epochs; on this host that
  is up to ~12 ms of host-side settlement after a staged upload. The call never waits
  for unfinished device work (verified separately), but a test cannot rely on
  "the first poll sees a pending frontier" after queueing 100 MB of transfers, so
  `seam_publication` asserts monotonic readiness plus `await_frontier` instead.
- **Staging evidence uses the runtime's counters.** `seam_staging` round-trips payloads
  of exactly one chunk, one element under and over, and three chunks, and asserts the
  recorded completion events and that idle pinned staging stays under the configured
  bound. It does not force budget pressure (that would need a runtime configuration
  knob the seam does not expose yet).
- **Transfers write through the runtime's raw scope.** `t4a-cuda-runtime` has no
  "copy into this existing buffer" entry, so `upload_pending`/`download_pending` issue
  `cuMemcpyHtoDAsync`/`cuMemcpyDtoHAsync` inside `with_raw` on the runtime's own stream
  and record a checkpoint for readiness. The package keeps the pinned source and the
  destination value alive until the completion is observed. An upstream
  `upload_into`/`download_into` would remove the raw calls; it is a candidate follow-up
  rather than a U1 requirement.
- **`CudaEngine` stays `Send + !Sync`.** The compile-time `Send` assertion is in the
  engine module and the move-to-another-thread behaviour is a test; `!Sync` comes from
  an explicit `PhantomData<Cell<()>>` rather than inheriting the runtime's auto traits.

## Findings from the post-implementation review and their disposition

- **The device-to-host copy wrote through a `&[u8]`-derived pointer.** Fixed:
  `submit_download` takes the pinned buffer mutably and derives the pointer from
  `as_mut_slice().as_mut_ptr()`, so the device write is authorized by the borrow the
  package owns.
- **`synchronize` released the submission lock before draining the detached queue.**
  Fixed: the lock is held through reclamation, so a clone cannot enqueue a transfer it
  then detaches in the gap and have its pinned source freed while queued.
- **No failure-safe teardown.** Fixed: `CudaRuntimeState::drop` synchronises the stream
  and leaks the detached queue when completion cannot be proved.
- **Device ordinal is not runtime identity.** Fixed: publication, both transfer
  directions and `copy_to` compare allocation domains, so a second engine on the same
  device cannot accept (or publish) another engine's allocation.
- **Detached packages were never reclaimed except by the wrapper's `synchronize`.**
  Fixed: the queue carries each package's completion and is drained on `stats()` and
  on `synchronize`; only packages whose completion is observed are released, and a
  failed completion is kept for the next explicit observation. The separate atomic
  counter the review called duplicate is gone.
- **The download contract accepted an oversized buffer, and download drop/forget,
  rejection-and-retry and two-in-flight were untested.** Fixed: exact-length
  rejection restored and the four download assertions added, including a dtype
  rejection that returns the package.
- **Cross-engine coverage missed source reuse and a producer-dropped consumer copy.**
  Fixed: the source allocation is dropped and re-uploaded before the copied value is
  read, and a consumer copy is read after its producer engine is gone.
- **The staging evidence could pass with one whole-payload allocation.** Fixed: a
  small-budget case opens a runtime with 1 MiB chunks and a 4 MiB pending budget, so a
  3 MiB payload must chunk, and the test asserts the chunk count and that the
  retirement records drain.
- **Availability was probed through the CubeCL path.** Fixed: `cuda_next::gpu_available`
  probes the new runtime's own device count.
- **Guessed plan/descriptor shapes.** Fixed: the vendor call descriptors and the unused
  counter snapshot are deleted, `VendorOps` is one method over `OpDescriptor` and
  buffers, and the engine no longer carries never-installed adapter boxes.
- **`cuda_next`/`gpu` were public.** They are `#[doc(hidden)]` now, still reachable from the
  crate's own integration tests, and the worklog says so rather than claiming privacy.
- **The new `with_raw` sites were missing from the engine-entry allowlist.** Added with
  their boundary reasons; `scripts/audit-engine-entry.py` passes.
- **Typed causes.** `TransferSubmitError::Runtime`, `PublicationAdmissionError::Runtime`
  and `PublicationError::Runtime` now carry the original error in a box instead of a
  flattened string.

Two review items are recorded rather than changed: the `download_into` download type
stays separate from `PendingDownload` because a publication cannot hand over the value it
keeps owning, and `trybuild`'s `cuda_engine_is_not_clone` fixture reports a path-formatting
mismatch under `--features cuda-next` (`tenferro_gpu::cuda::CudaEngine` instead of
`CudaEngine`). The same class already fails on `origin/main` on this host (two fixtures,
the known `/kache` artifact); the compile-fail behaviour itself is unchanged, since the
type still does not implement `Clone`.

## Not done (U2 and later)

- No operation surface: `TensorElementwise`/`TensorStructural`/… still come from the
  CubeCL backend, and `KernelSource`/`VendorOps` return `Unsupported`.
- No feature removal: `cubecl*`, `webgpu`, the macOS lane and the `t4a-cubecl`/
  `t4a-cubek` pins stay until U6.
