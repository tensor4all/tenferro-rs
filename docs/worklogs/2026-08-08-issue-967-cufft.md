# Work log: issue #967 CUDA/cuFFT execution

## Session summary

Issue [#967](https://github.com/tensor4all/tenferro-rs/issues/967) requested
CUDA/cuFFT execution for the existing one-dimensional `fft`, `ifft`, `rfft`, and
`irfft` operations without changing their public APIs or moving tensor payloads
implicitly between host and device. The final candidate is commit
`2c9ecbfa2346b5686746088c113f02a36df30bb1` (24 issue-lane commits after
`origin/main` at `3678a75bccaba7181d7e9ace46d45a6915ce36b7`).

The implementation keeps host execution on RustFFT and adds explicit CUDA
execution for concrete, eager, and traced paths. It adds no new operation
surface, no CPU fallback, no hidden plan cache, and no standalone design or
plan artifact to the PR. The earlier
`docs/worklogs/2026-08-08-issue-967-cufft-task6-round2.md` is consolidated here
and deleted; this file is the single authoritative issue worklog.

## Implementation ownership and decisions

1. **Keep public semantics and placement explicit.** Existing FFT traits and
   signatures remain unchanged. `tenferro-fft` validates exact
   `CudaRuntime` residency and compact column-major layout; host and foreign
   tensors return typed errors. CUDA execution never uploads, downloads,
   constructs a CPU backend, or calls RustFFT.
2. **Make cuFFT operation-family-owned.** `tenferro-fft` owns the dynamic
   `libloading` loader, ABI function table, checked descriptors, opaque plans,
   CubeCL workspaces, the `cufft-plans` namespace, and typed status/lifecycle
   errors. The loader tries non-empty `TENFERRO_CUFFT_PATH` entries followed by
   CUDA 12, CUDA 11, and bare sonames. The loaded `Library` is retained with
   every plan; no process-global or thread-local loader state exists.
3. **Use explicit non-null rank-one embeds.** The final-axis
   `PlanMany64` descriptor uses `istride = ostride = batch` and
   `idist = odist = 1`, with owned non-null `[i64; 1]` `n`, `inembed`, and
   `onembed` arrays. C2C uses `[n]/[n]`, R2C `[n]/[n / 2 + 1]`, and C2R
   `[n / 2 + 1]/[n]`. Products and conversions to cuFFT integer widths are
   checked before the FFI boundary.
4. **Canonicalize with existing CUDA operations.** The selected axis moves to
   the final logical axis by the existing device transpose (the final-axis
   case skips it). C2C/R2C inputs are sliced or zero-padded on device for an
   explicit `n`; C2R consumes the validated half-spectrum unchanged and uses
   `n` only as the real output length. No custom packing kernel, direct-stride
   heuristic, or multidimensional FFT was introduced.
5. **Keep cache ownership where it already belongs.** Repeated concrete calls
   use the caller-owned `FftExecutionCache`; eager and traced calls use the
   runtime-owned extension cache. The exact runtime-aware key is retained in
   each entry, so a discriminator collision cannot reuse a different plan.
   Existing entry/byte limits, LRU eviction, clear, stats, and retirement are
   the only controls; no backend-hidden or second cache was added.
6. **Bind the current stream at enqueue time.** Each execution sets the
   retained runtime context current, binds the current CubeCL stream with
   `cufftSetStream` immediately before the dtype-specific call, and keeps the
   stream and input/output device pointers inside scoped callbacks. The launch
   path does not synchronize. The current runtime exposes one serialized
   current stream through the mutable backend-session boundary.
7. **Retire synchronously, and leak only when safety cannot be proved.** Normal
   cache eviction/clear first makes the retained context current and
   synchronizes its current stream, then destroys the plan and releases the
   CubeCL workspace. If context activation, synchronization, or destruction
   fails, the complete plan/workspace/library/runtime witness bundle is
   intentionally retained (leaked) and a non-panicking cleanup diagnostic is
   emitted. This is the only retirement leak path; successful retirement does
   not leak. Event-based deferred retirement was not added.
8. **Use an owner-scoped output scaling bridge.** `tenferro-gpu` owns the
   narrow `scale_tensor_write` interop helper, reusing existing structural
   scale kernels and scoped allocation/pointer APIs. cuFFT remains out of place;
   the helper scales the separate writable output buffer on device, preserving
   input immutability and avoiding unrestricted pointer exposure.
9. **Complete real spectra with existing device operations.** Real-input full
   `fft` runs R2C/D2Z, then performs normalization and Hermitian completion on
   device using existing slice, reverse, conjugate, and concatenate operations.
   DC and the even-length Nyquist bin are not duplicated; odd/even and `n=1`
   and `n=2` cases are covered.
10. **Keep eager dispatch owner-selected and transactional.** `tenferro-ad`
    resolves the exact `EngineId` and closed backend kind supplied by the eager
    runtime owner. The FFT crate matches that kind only to its existing
    CPU/CUDA/WebGPU module factory; it does not infer a backend from placement
    or invent an engine ID. Input ingress is checked before factory invocation.
    `RuntimeReconfiguration::replace_extension_module_for_engine` configures
    and validates a candidate module's exact family/engine registration before
    atomically publishing it, so a failed replacement leaves the prior snapshot
    intact. The bridge then enters the existing non-owning backend session.

## Alternatives rejected or deferred

- CPU fallback, RustFFT fallback, implicit upload/download, and placement-based
  backend inference were rejected: unsupported or misplaced CUDA inputs must
  fail explicitly at their owned boundary.
- In-place real FFT was rejected because cuFFT's real in-place layout and
  overwrite/padding constraints would complicate the compact column-major
  contract; all transforms are out of place.
- Custom pack/unpack or fused Hermitian kernels were rejected in favor of the
  existing CUDA transpose, slice, pad, reverse, conjugate, concatenate, and
  scaling operations. Specialized kernels can be reconsidered only after a
  benchmark demonstrates a material bottleneck.
- Hidden backend/global/thread-local caches were rejected in favor of the
  existing caller/runtime-owned `FftExecutionCache`. Process-global loader
  state was likewise rejected so library lifetime follows explicit cache and
  plan ownership.
- Unrestricted raw stream or device-pointer exposure was rejected. The
  `tenferro-gpu` callbacks borrow each handle only for the FFI/launch scope.
- Event-based deferred retirement was rejected for the current serialized
  stream model; synchronized retirement is simpler and makes the safety
  boundary explicit. It may be revisited only if measured cache churn makes
  the synchronization cost material.
- Aggregate extension lookup, placement inference in `tenferro-ad`, and
  non-transactional eager installation were rejected because another module
  could mask a mismatch or a failed candidate could replace a valid snapshot.

## Remaining risks and follow-up

- The current CUDA runtime deliberately serializes one current stream. Before
  selectable concurrent streams are supported, stream identity and
  per-stream workspace ownership must be added to the cache key and retirement
  model.
- Cleanup failure intentionally retains/leaks the complete resource witness
  bundle. This is bounded by failure paths and is safer than freeing resources
  while queued work may still reference them; normal retirement synchronizes,
  destroys, and releases resources.
- No second GPU or multi-stream execution path was exercised. WebGPU execution
  remains hardware-gated and unrelated; its compile checks do not claim runtime
  support for this feature.
- A broad autodiff all-target clippy/test command still encounters four
  pre-existing `tests/fft_ops.rs` calls to `Tensor::clone()`; the focused CPU
  FFT, eager library, CUDA target, and doctest checks pass, and unrelated test
  cleanup was intentionally excluded.
- Full workspace coverage, release-mode, and final hosted-CI matrix remain the
  integration/PR verification boundary; this worklog records task-local and
  documented hardware evidence rather than claiming those gates ran here.
