# Work log: issue #967 CUDA/cuFFT execution

## Session summary

Issue [#967](https://github.com/tensor4all/tenferro-rs/issues/967) adds CUDA/cuFFT
execution for the existing one-dimensional `fft`, `ifft`, `rfft`, and `irfft`
operations. Public signatures and operation names remain unchanged. Host
execution remains on RustFFT; CUDA execution is explicit for concrete, eager,
and traced paths, with no implicit host/device movement.

Session provenance was the issue, its approved working design, and its approved
implementation plan. Those standalone working artifacts are not linked here
and are excluded from the external PR. This file is the concise durable record;
the eventual PR should link it and issue #967.

## Ownership and durable decisions

1. **Placement and API semantics stay explicit.** `tenferro-fft` validates exact
   `CudaRuntime` residency and compact column-major layout. Host tensors and
   tensors from a foreign runtime return typed errors. CUDA code never uploads,
   downloads, constructs a CPU backend, or calls RustFFT.
2. **The FFT crate owns cuFFT.** `tenferro-fft` owns the dynamic `libloading`
   loader, ABI table, descriptors, opaque plans, the `cufft-plans` namespace,
   typed lifecycle errors, and CubeCL workspaces associated with its plans.
   Non-empty `TENFERRO_CUFFT_PATH` entries are tried first, followed by
   `libcufft.so.11`, `libcufft.so.10`, and bare `libcufft.so`, covering CUDA
   12/cuFFT 11 and CUDA 11/cuFFT 10. The loaded library is retained by each plan;
   there is no process-global or thread-local loader state.
3. **Descriptors make the column-major contract explicit.** After the selected
   axis is moved last, `PlanMany64` uses `istride = ostride = batch` and
   `idist = odist = 1`. Owned non-null rank-one `n`, `inembed`, and `onembed`
   arrays are always passed. C2C uses `[n]/[n]`, R2C `[n]/[n / 2 + 1]`, and C2R
   `[n / 2 + 1]/[n]`. Shape products and conversions to cuFFT integer widths
   are checked before the FFI boundary.
4. **Existing device operations do canonicalization.** CUDA transpose moves
   the requested axis to the final logical axis and the inverse permutation
   restores it. C2C and R2C inputs are sliced or zero-padded on device for an
   explicit `n`; C2R consumes the validated half-spectrum unchanged and uses
   `n` only as the real output length. No custom packing or direct-stride path
   was introduced.
5. **The existing cache remains the owner.** Repeated concrete calls use the
   caller-owned `FftExecutionCache`; eager and traced calls use the owning
   runtime's extension cache. Exact runtime identity, device, dtype/kind,
   direction, length, batch, and stride facts are retained in the key/value, so
   a discriminator collision cannot reuse a different plan. Existing entry and
   byte limits, LRU eviction, clear, stats, and retirement are the only cache
   controls.
6. **Scoped pointer safety supersedes the initial async intent.** An earlier
   design intent allowed cached cuFFT calls to remain asynchronous between
   eviction events. An independent safety review found that scoped CubeCL raw
   pointers carry no completion witness, so that intent is superseded for #967.
   Each execution makes the retained context current, binds the current CubeCL
   stream immediately before the dtype-specific cuFFT call, and keeps stream
   and device pointers inside scoped callbacks. Separate read and exclusive
   write leases retain the prepared input/output CubeCL handles and exact
   runtime through a stream synchronization inside the innermost output-pointer
   callback, after vendor enqueue and before pointer use ends. Successful
   synchronization therefore completes before the input-pointer and raw-stream
   callbacks return and drops both leases; a synchronization failure
   intentionally retains them so vendor work cannot race allocation
   reclamation, while enqueue and synchronization failures preserve
   primary/suppressed typed errors. Future asynchronous execution requires a
   separately accepted event-backed external-use ownership design and is
   outside #967. The current runtime has
   one serialized current stream through the mutable backend-session boundary,
   so stream identity is omitted from the key. If selectable concurrent streams
   are added, stream identity and per-stream workspace ownership must enter the
   key before reuse.
7. **Retirement favors safety over forced cleanup.** Eviction and clear make the
   retained context current and synchronize its stream before destroying the
   plan and releasing its workspace. Cleanup failures are non-panicking. If
   context activation, synchronization, or destruction cannot be proved safe,
   the complete plan/workspace/library/runtime witness bundle is intentionally
   retained rather than freed while queued work may still reference it.
8. **Scaling is a narrow owner-scoped bridge.** `tenferro-gpu` owns the generic
   `scale_tensor_write` interop helper, reusing structural scale kernels and
   scoped allocation/pointer APIs. cuFFT stays out of place; scaling writes the
   separate output buffer without exposing unrestricted raw pointers.
9. **Real full spectra stay on device.** Real-input `fft` runs R2C/D2Z, applies
   normalization, then uses existing slice, reverse, conjugate, and concatenate
   operations. DC and the even-length Nyquist bin are not duplicated; odd/even
   lengths, including the small lengths one and two, follow the same rule.
10. **Eager selection is owner-selected and transactional.** `tenferro-ad`
    resolves the exact `EngineId` and closed backend kind supplied by the eager
    runtime owner. FFT matches that kind only to its existing CPU/CUDA/WebGPU
    module factory; it does not infer placement or invent an engine ID. Input
    ingress is validated before factory invocation. Proposed module registration
    validates the exact family/engine pair before atomic publication, so a failed
    replacement leaves the prior runtime snapshot intact. The bridge
    then enters the existing non-owning backend session.

## Rejected or deferred alternatives

- CPU/RustFFT fallback, implicit upload/download, and placement-based backend
  inference were rejected: unsupported or misplaced CUDA input must fail at its
  owning boundary.
- In-place real FFT was rejected because cuFFT's padding and overwrite rules do
  not fit the compact column-major contract cleanly; all transforms are out of
  place.
- Custom pack/unpack, fused Hermitian kernels, and shape-dependent direct
  strides were deferred. Existing transpose, slice, pad, reverse, conjugate,
  concatenate, and scale operations are the smallest complete implementation;
  specialized kernels need a measured bottleneck first.
- Hidden backend/global/thread-local caches and process-global loader state were
  rejected in favor of caller/runtime-owned cache and explicit plan lifetime.
- Unrestricted raw stream or pointer exposure was rejected; interop callbacks
  borrow each handle only for the FFI or launch scope.
- Event-based deferred retirement and event-backed asynchronous external use
  were deferred for the current serialized-stream model. They may be reconsidered
  only in a separately accepted follow-up if measured cache churn makes
  synchronized retirement material; that follow-up is outside #967.
- Aggregate extension lookup, placement inference in `tenferro-ad`, and
  non-transactional eager installation were rejected because they can mask a
  mismatch or replace a valid snapshot with a failed replacement.

## User behavior and documentation

The API remains the existing concrete, eager, and traced FFT surface with the
same dtypes, axes, lengths, and normalization modes. CUDA users transfer
explicitly, select a CUDA runtime/session, and can verify device residency before
download. Missing cuFFT, foreign residency, unsupported combinations, and invalid
configuration produce typed errors; a zero non-transform extent returns a
correctly shaped empty CUDA output before library loading or plan creation.

The guide documents CUDA setup, `CUDA_PATH`, `LD_LIBRARY_PATH`,
`CUBECL_DEBUG_LOG`, `TENFERRO_CUFFT_PATH`, CUDA 12/cuFFT 11 and CUDA 11/cuFFT 10
candidate compatibility, explicit transfer boundaries, and limitations. The
runnable tutorial emits an explicit no-device marker or fails in strict mode;
its strict A100 path checks residency and explicit download. The cuFFT FFI
boundary synchronizes vendor work, while the explicit download synchronizes
stream-managed postprocessing. Durable execution and GPU ownership contracts
are in the linked design documents.

- The CUDA runtime serializes one current stream. Selectable concurrent streams
  require per-stream cache identity, workspace ownership, and retirement.
- Cleanup failure intentionally retains the complete witness bundle; this is
  bounded to failure paths and safer than freeing resources with queued work.
- No second GPU or multi-stream path was exercised. WebGPU runtime execution is
  hardware-gated and outside this change.
- A broad autodiff all-target clippy/test invocation still shows four
  pre-existing `tests/fft_ops.rs` calls to `Tensor::clone()`; unrelated cleanup
  is out of scope. Full coverage and hosted CI remain PR integration gates.
