# Documentation Integration (Design + API)

Date: 2026-02-15

## Goal

Publish a single review-friendly documentation site that combines:

- Design documents in `docs/design/`
- API reference generated by `cargo doc`

## Recommended Output Structure

```text
site/
  index.html          # project top page
  design/             # rendered docs/design pages
  api/                # rustdoc output (workspace crates)
```

## Build Flow

1. Build API docs

```bash
cargo doc --workspace --no-deps
```

Rustdoc output is generated under `target/doc/`.

2. Build design docs HTML

- Option A: mdBook (recommended for multi-page navigation)
- Option B: Pandoc or static markdown-to-html conversion

3. Assemble site directory

- Copy rustdoc to `site/api/`
- Copy design HTML to `site/design/`
- Provide `site/index.html` with links to both sections

Repository helper:

```bash
./scripts/build_docs_site.sh
```

Default output:

- `target/docs-site/index.html`
- `target/docs-site/design/*.html`
- `target/docs-site/api/*`

## Top Page Content (Minimum)

- Current project phase (POC / API skeleton)
- "Read design docs" link
- "Browse API reference" link
- Note describing implemented vs planned areas

## Cross-linking Rules

- From design docs: link to crate rustdoc pages (`/api/tenferro_autodiff/`, etc.)
- From crate-level rustdoc: link back to design docs (`/design/tenferro_design.html`)
- Keep links relative so the site can be hosted on GitHub Pages or local file server

## Why This Split Works

- `docs/design` explains architecture and rationale
- rustdoc explains signatures and usage examples
- single top page removes reviewer confusion and shortens onboarding time
