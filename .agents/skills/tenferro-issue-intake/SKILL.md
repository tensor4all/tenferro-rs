# Tenferro Issue Intake

Follow `ai/contribution-workflows/issue-intake.md` as the canonical workflow.

Read that file before drafting. Ask the user only for missing judgment calls or
facts that cannot be discovered from the repository or GitHub state.

Keep the interaction incremental:

1. Classify the issue type.
2. Collect the goal and current friction.
3. Gather reproduction details or use-case details.
4. Apply the contribution scope gate.
5. Draft title, body, acceptance criteria, and provenance notes.
6. Wait for confirmation before creating the issue unless the user explicitly
   asked for direct creation.
