# Public API snapshots

One file per published crate and feature combination, generated by
`cargo public-api -ss` (blanket and auto-trait impls omitted). The snapshot was
introduced for [#2552](https://github.com/tensor4all/tenferro-rs/issues/2552) so
that every change to the public surface shows up as a diff in review.

**A snapshot is review evidence, not a proof of behaviour.** It shows which
names and signatures exist. Layout handling across adapters, aliasing,
ownership, destination updates and numerical results are checked by tests.

## Files and feature combinations

The combinations are fixed in `scripts/api-snapshot.sh`; change the script and
this table together.

| File | Crate | Features |
|---|---|---|
| `<crate>.txt` | every crate below | default features |
| `tenferro-internal-ops+all.txt` | `tenferro-internal-ops` | `autodiff,cuda` |
| `tenferro-gpu+native-cuda.txt` | `tenferro-gpu` | `native,cuda` |
| `tenferro-xla+pjrt.txt` | `tenferro-xla` | `pjrt` |
| `tenferro-einsum+autodiff-native-cuda.txt` | `tenferro-einsum` | `autodiff,native,cuda` |
| `tenferro-ad+native-cuda.txt` | `tenferro-ad` | `native,cuda` |
| `tenferro-linalg+autodiff-native-cuda.txt` | `tenferro-linalg` | `autodiff,native,cuda` |
| `tenferro-fft+autodiff-native-cuda.txt` | `tenferro-fft` | `autodiff,native,cuda` |

The second combination of a crate is its docs.rs feature set. `tenferro-cpu`
and `tenferro-runtime` have one file each, because their docs.rs set
(`native`) is the default set.

`allowlist.txt` is not a snapshot: it lists, symbol by symbol, the approved
external types and owner-scoped bridges of exception E06 (see the core
registry, `crates/tenferro-runtime/src/api/registry.rs`).

Not snapshotted:

- `publish = false` packages (`docs/tutorial-code`, the `ext/*` proof and
  consumer crates, and the standalone `ext/sparse` and `ext/tropical`
  manifests).
- `tenferro-internal-extension-macros`: a proc-macro crate, for which rustdoc
  emits no JSON.
- BLAS-provider features (`blas`, `blas-*`, `provider-inject`): they select a
  backend implementation and are mutually exclusive with `native`.

## Updating

```bash
scripts/api-snapshot.sh --write   # regenerate api/*.txt
git diff api/                     # review: removed and added items
scripts/api-snapshot.sh --check   # what CI runs (placement job)
```

Commit the regenerated files in the same change as the code. A pull request
that changes the public API without updating `api/` fails the `placement` job.

The tool needs `cargo-public-api` and a nightly toolchain for rustdoc JSON. CI
uses the nightly that `dtolnay/rust-toolchain@nightly` installs; if a nightly
update changes the rendering without an API change, regenerate with that
nightly.
